# RFC 2119 keyword pick

Meanings live in `SKILL.md`. This file is the pick rule.

## Pick

| Keyword | Pick when |
| --- | --- |
| MUST | Skip causes an error, data loss, a security hole, or a broken invariant. The next step cannot run without it. |
| MUST NOT | The action corrupts data, leaks secrets, or breaks an invariant. |
| SHOULD | Quality, safety, or speed improves, and a real alternative exists. |
| SHOULD NOT | The approach is an anti-pattern. Name the exception if one exists. |
| MAY | The step is optional. Skipping it leaves the SOP correct. |

A MUST is testable. "Try to", "be careful", and style nits are SHOULD or MAY.

## Patterns

Mix levels in one step:

```markdown
1. Apply the migration
   - You MUST backup the database
   - You SHOULD run the migration in a maintenance window
   - You MAY notify the team in chat
```

Conditionals keep the keyword on the action:

```markdown
1. Check the feature flag
   - If enabled: you MUST use the new path
   - If disabled: you MUST use the legacy path
```

Order inside a step: MUST, then SHOULD, then MAY.

## Failures

| Wrong | Right |
| --- | --- |
| MUST for indentation or quote style | SHOULD follow the project style |
| MUST try to write good tests | MUST run the test suite and get a pass |
| SHOULD avoid eval | SHOULD NOT use eval, except in a sandbox |
| MUST validate input, and MAY skip validation | MUST validate untrusted input. You MAY cache a pass |

A MUST and a MAY that cancel each other is a defect. Rewrite until one keyword owns the action.

## Fragment

```markdown
1. Open the change
   - You MUST read the diff before you comment
   - You MUST NOT approve hardcoded secrets
   - You SHOULD check tests cover the new branch
   - You MAY note a naming nit
```

Done: every requirement line has one keyword, and a reader can tell required from optional without guessing.
